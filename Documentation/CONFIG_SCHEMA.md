# VisualFX Configuration Schema (version 1)

> Generated by `tools/gen_docs.sh` from the live registries. Machine-readable forms:
> `schema/config.schema.json` (JSON Schema draft-07), `schema/visualfx.schema.json` (full VisualFX schema
> including weather types, particle templates, director vocabulary and commands), `schema/presets.json`.

A configuration is a plain table. Every key is optional; only sections that
are present are managed. Unknown keys produce warnings (with suggestions) and
are ignored.

```lua
{
    Version = 1,
    Metadata = { Name = "Cinematic Sunset", Author = "VisualFX", Description = "...", Category = "Cinematic", Tags = { "sunset" } },
    Inherits = { "Sunset" },            -- optional preset composition
    Quality = { Level = "High" },
    Lighting = {...}, Atmosphere = {...}, Sky = {...}, Clouds = {...},
    PostProcessing = { Bloom = {...}, ColorCorrection = {...}, DepthOfField = {...}, SunRays = {...}, Blur = {...} },
    Water = {...},
    Particles = { [name] = {...} },
    Weather = { Type = "HeavyRain", Intensity = 0.8, ... },
    Environment = { Wind = {...}, DayNight = {...}, Zones = { [name] = {...} } },
    Effects = { [id] = { Effect = "<registered effect>", ... } },
}
```

## Properties of the format

* **Deterministic.** Exports sort keys (priority keys such as `Version`, `Metadata`, `Type` first) and print numbers with the shortest round-tripping form. The same configuration always produces byte-identical JSON, so exports are diffable.
* **Serializable.** Roblox values use tagged JSON encodings (below); `ImportConfiguration` accepts tables, `VisualFXConfig` documents and JSON text.
* **Versioned.** `Version` is the schema version. A configuration without `Version` is treated as version 0 and migrated.
* **Validated.** Every configuration is validated before use (types, ranges, enums, required fields, references, compatibility, conflicts, performance).
* **Composable.** `Inherits` merges presets left to right before the configuration's own values.

## Merge rules

Used by `UpdateScene`, `Set*` setters, preset inheritance and transitions:

1. Scalars and Roblox values in an overlay replace the base value.
1. Dictionaries merge recursively, key by key.
1. Arrays are replaced as a whole.
1. The string "$remove" deletes a key.
1. Keys are processed in sorted order.

## Value encodings

In Luau you pass Roblox values directly. JSON (and AI agents) can use either
the tagged form or a shorthand; both are validated and converted.

| Kind | Tagged JSON | Shorthands |
| --- | --- | --- |
| Color3 | `{"$type":"Color3","rgb":[190,205,220]}` | `#BECDDC`, `[190, 205, 220]` |
| ColorSequence | `{"$type":"ColorSequence","keypoints":[[0,255,255,255],[1,0,0,0]]}` | `#FFFFFF`, `[[255,255,255],[0,0,0]]` |
| EnumItem | `{"$type":"EnumItem","enum":"NormalId","name":"Top"}` | `"Top"` |
| NumberRange | `{"$type":"NumberRange","max":2,"min":1}` | `1.5`, `[1, 2]` |
| NumberSequence | `{"$type":"NumberSequence","keypoints":[[0,0.1,0],[1,0.3,0]]}` | `0.2`, `[0.1, 0.3]` |
| Vector2 | `{"$type":"Vector2","xy":[3,3]}` | `[3, 3]` |
| Vector3 | `{"$type":"Vector3","xyz":[0,30,0]}` | `[0, 30, 0]` |

Enum items may also be given by name (`"Box"`, case-insensitive) or by value number. Enum item lists in the JSON Schema reflect the generator's engine model; the running engine is always authoritative.

## Schema migration

| From | To | Changes |
| --- | --- | --- |
| 0 (unversioned) | 1 | `Lighting.PostProcessing` → `PostProcessing`; `Particles` array → dictionary keyed by `Name`; `Weather = "Type"` → `{ Type = "Type" }`; `Water.WaterColor`/`WaterTransparency`/... → `Water.Color`/`Transparency`/... |

Newer versions than the runtime supports are rejected with a clear error.

A system's `Template` defaults to its name when that matches a template,
otherwise `Custom`. Configured values override template defaults. `Rate` is
scaled by the quality profile and budgets (see PERFORMANCE.md).

Weather blends the scene's own values (or Roblox defaults when a section is
not configured) toward the weather's targets by `Intensity`. `Fog` adds
Atmosphere density/haze (and ground mist at ≥ 0.45). `Wind` sets
`Workspace.GlobalWind` unless `Environment.Wind` is configured, and pushes
rain/snow sideways. Component intensities (`RainIntensity`, …) override
`Intensity` for that component. Weather-owned instances are replaced, never
accumulated, when the weather changes.
